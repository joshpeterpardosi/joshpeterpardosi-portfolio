MLOps Pipeline — Churn Prediction & Revenue Forecasting

Python · Dagster · MLflow · LightGBM · FastAPI · Evidently · Docker

Built an end-to-end MLOps loop for a SaaS subscription business — Dagster orchestrates ingestion through training, MLflow tracks and promotes both the churn and forecast models by their evaluation metric, a FastAPI service serves live predictions, and an Evidently-monitored drift sensor triggers retraining automatically.

101 tests run standalone in CI — mocks and tmp_path only, no live dataset or trained model required — and the docker-compose stack was verified end-to-end, serving real predictions from the production-aliased churn model at 0.84 ROC-AUC.

The forecast model's RMSE (38.96) barely beats a naive baseline (39.06), and churn recall sits at 0.51 — it still misses roughly half of actual churners, so neither model is tuned for production-grade capture yet.

E-Commerce Conversion Funnel & Customer Retention Platform

DuckDB · Python · Parquet · Streamlit · Plotly · Pytest

Built an end-to-end analytical platform that queries 507,928 clickstream events and 25,000 customer records directly on Parquet with DuckDB — no database server — behind a four-page Streamlit dashboard covering funnel, cohort retention, RFM segmentation and an automated data-quality audit. The heaviest query, five sequential session joins with windowing, returns in ~179 ms.

The funnel credits a stage only when it follows the previous one inside the same session: 25,000 visitors narrow to 2,033 purchasers (8.13%), and the steepest recoverable leak is product_view → add_to_cart at 54.50%. RFM isolates 113 Champions averaging $394.47 against $102.02 for churned accounts, a 3.9× gap, and cohort retention decays 100% → 75.2% → 56.8% → 37.2% over the first three months. 11 tests run the production SQL against fixtures with hand-computed answers, on CI across Python 3.12–3.14.

The data is synthetic — conversion behaviour is configured by the generator rather than observed, so these figures show the pipeline computes the metrics correctly, not that they reveal real customer behaviour.

Data Quality & Observability Platform

Python · DuckDB · Pandera · Streamlit · Plotly · Pytest

Built an end-to-end pipeline that ingests messy e-commerce CSVs into DuckDB, validates them against data-quality rules across five dimensions — completeness, uniqueness, validity, consistency, timeliness — and curates only the rows that pass into a three-page observability dashboard.

20 tests cover every validation layer end to end — Pandera schemas, SQL checks, and the curation gate — with CI running the full suite on every push across Python 3.11 and 3.13.

No scheduler yet — checks run on demand, not on a cron, so freshness is enforced by hand until an orchestrator like Airflow or Dagster is added.

Real-Time Event Pipeline — Fraud/Transaction Detection

Kafka (Redpanda) · Python · ClickHouse · XGBoost · Grafana · Streamlit · Docker

Built a streaming pipeline that ingests transaction events through Kafka and scores each one twice — a rule engine covering amount thresholds, per-user velocity and geo mismatch, plus an XGBoost model — then writes both raw and flagged events into ClickHouse, behind a Grafana pipeline-health board and a Streamlit analyst view.

Every flagged transaction carries its own fraud_reason, so an analyst can see whether a rule fired, the model did, or both. The model has to clear an enforced precision/recall bar (0.80 / 0.70) before it can be used at all; the one in the repo passed at 0.846 precision and 0.786 recall on the Kaggle held-out split. 46 tests cover the rule engine, the consumer loop, and one end-to-end run against the live docker-compose stack.

ML scoring only applies to replayed Kaggle transactions. The synthetic generator does not emit the model's feature space, so synthetic traffic is checked by rules alone — a data-availability limit written into the schema rather than papered over.
